# V1.0.8-dev.4 本地预览

日期：2026/10/22。包含 dev.3 的全部改进，仅供本地手动检查；不发布到 GitHub，不自动覆盖安装 PC 或 Android。

## 配对与网络配置

- 主 PC 的“配对新设备”弹窗直接显示本次邀请对应的待配对设备及六位设备码；确认匹配成功后自动关闭，失败则保留弹窗和错误提示。
- 监听网络接口通过“新增…”加入后立即切换；服务正在运行时重新绑定所选接口。默认接口仍由星标单独控制。
- 首次配对自动将二维码中的实际监听地址、端口保存为客户端连接配置，无需重复输入。
- 已配对 Android 和 Windows 客户端增加主机连接配置下拉列表，保留成功认证过的地址/端口；可切换历史配置，也可通过“新增…”验证后添加。
- 两端客户端均可通过星标设置默认连接，列表标记“默认”。下次正常启动优先尝试默认项；手动临时切换不改变默认项。
- 主 PC 增加“更新 WLAN”二维码；Android 扫码、Windows 粘贴更新码后可验证、保存并切换主机地址，无需重新配对。原地址保留在下拉列表中。
- 手动编辑地址/端口保留为折叠的备用入口。

## 安全与兼容

- 更新码有效期 10 分钟，只用于已配对的同一同步组及同一主 PC；不包含邀请 token，也不授予新设备配对权限。
- 保存新地址前验证原 TLS 证书指纹，并完成已配对设备的签名会话认证；身份不符、过期码、错误证书和认证失败不会覆盖原配置。
- 不变更 Schema v5 或同步协议；旧连接配置自动补齐当前地址为历史项及默认项。地址历史、默认项不参与任务 JSON 备份或多端数据同步。
- 校园网地址是否可达仍取决于实际网络策略，扫码不能穿透客户端隔离。主 PC 必须监听所选接口，异地可继续使用 Tailscale。
- 保留 dev.3 数据库兼容修复。不要用旧版程序交替打开升级后的同一数据库；需要回退应使用升级前备份。

## 手动检查步骤

1. PC 选择实际 WLAN 监听接口，若从“新增…”添加，检查列表已自动切换且服务运行正常。
2. 首次配对：手机扫码后，保持 PC 配对弹窗打开，检查设备码在弹窗内出现；核对并确认，检查弹窗自动关闭且手机同步成功。
3. 已有配对：PC 点击“更新 WLAN”，手机“设置 → 多端同步 → 扫码更新 WLAN”，检查自动保存地址并同步，原连接记录仍在。
4. 手机下拉切换连接，点击星标设为默认；临时切到另一个地址后重启应用，检查优先连接默认地址。Windows 客户端行为相同。
5. 用其他主 PC 或已过期的更新码测试，检查拒绝更新且原配对、地址及任务都保留。
