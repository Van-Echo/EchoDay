# V1.0.8-dev.3 本地修复预览

日期：2026/10/22。仅用于本地检查，不发布到 GitHub。

包含 dev.2 的全部功能，修复旧数据库在升级时无法打开、进而导致任务加载及同步主机启动失败的问题。

## 数据库兼容修复

- 兼容实际字段已经添加、但 SQLite `user_version` 仍为 v3/v4 的数据库。
- v4/v5 的新增字段迁移先检查实际结构，兼容的现有字段及其值全部保留，仅添加缺少的字段，不重建或清空数据表。
- 同一次结构迁移使用事务；遇到不兼容的列类型或数据时停止并回滚，不盲目改写版本号。
- 新版拒绝对未知更高版本数据库进行降级，避免自身静默降低版本标记。
- 注意：已发布旧程序不具备这个保护。升级后不要交替使用 1.0.7 等旧版打开同一数据库；需要回退时应使用升级前的备份。
- 未更改 Schema v5、同步协议、设备身份或证书。已使用 dev.2 的客户端与 dev.3 协议兼容；仍为 1.0.7 的客户端建议一并升级。

已在当前故障数据库的备份副本上验证：恢复到 Schema v5 后，17 张表的全部数据行哈希均保持一致，172 条任务、9 条设备记录保留，SQLite 完整性检查通过。副本测试未修改原数据库。

## TJ-WIFI 直连实测

2026/10/22 临时将主 PC 的监听接口切到 WLAN，手机强制通过 `wlan0` 访问主 PC 校园网地址。连续三次请求 EchoDay HTTPS `/v1/info` 均返回 HTTP 200，请求总耗时约 36～71ms。证明这两台设备在当时的 TJ-WIFI 下可直接连接，不必依赖 Tailscale。

以上是网络连通测试，并非完整任务同步验收。测试后已恢复原 Tailscale 监听配置，未关闭或修改防火墙。

如需纯校园网同步，请在电脑端选择 WLAN 监听接口，并在新版手机“设置 → 多端同步”中将主机地址和端口改为电脑显示的校园网服务地址，再点击“保存并重试”。校园网 DHCP 地址可能变化，应以当前实际显示为准。
