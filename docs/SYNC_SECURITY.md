# EchoDay V1 同步威胁模型与日志规范

> 状态：S3 已实现
> 日期：2026-09-09

## 1. 信任边界与资产

需要保护的资产包括 TODO 正文和备注、分类标签、同步历史、设备身份私钥、配对邀请、会话密钥、主机地址及设备备注。

边界：

- 本机数据库与应用进程；
- Windows 主机监听 Socket；
- 局域网或 Tailscale 提供的 IP 网络；
- Android/Windows 客户端；
- 操作系统安全存储；
- 用户选择的 JSON 备份目录。

Tailscale 只提供网络可达性，不替代 EchoDay 配对、主机指纹固定和双向设备认证。处于同一局域网或 Tailnet 的设备默认仍不可信。

## 2. 主要威胁与控制

| 威胁 | 影响 | V1 控制 |
| --- | --- | --- |
| 未配对设备枚举/读取数据 | 隐私泄露 | info 只暴露最小版本信息；数据端点必须认证 |
| 中间人替换主机 | 数据泄露或篡改 | 二维码/连接码固定主机公钥指纹；加密会话 |
| 二维码被拍摄复用 | 未授权配对 | 128-bit 以上随机 token、只存哈希、5 分钟过期、单次使用、失败次数限制、主机人工确认 |
| 请求重放 | 重复修改或游标欺骗 | 会话 nonce/时间窗口、operation ID 幂等、ID 内容绑定、连续 sequence |
| 恶意或损坏 payload | 崩溃、注入、磁盘耗尽 | 解压后大小、批次数、深度和字符串限制；枚举白名单；事务校验 |
| 错误设备时间 | 错误覆盖 | 因果游标优先，HLC 逻辑计数，device ID 稳定决胜 |
| 主机/客户端中途断电 | 部分应用 | 数据和 change 同事务；按确认游标续传 |
| 删除被离线设备复活 | 数据不一致 | 墓碑、逐设备确认、安全保留窗口、快照墓碑基线 |
| 私钥进入备份或日志 | 长期身份泄露 | `DeviceSecretStore`；秘密不进 SQLite 普通表、JSON、日志或 Crash 文本 |
| 服务暴露到公网 | 扫描和攻击面增加 | 默认仅用户选择的私有接口；不做 UPnP/NAT 映射；关闭模式立即释放端口 |
| 本地恶意用户读取数据 | 本机隐私泄露 | 依赖 OS 账号/磁盘安全；V1 不承诺数据库全文加密 |

## 3. 配对与密钥基线

- 每设备首次启用时生成独立公私钥对和永久 device ID。
- Android 使用 Keystore 支持的安全存储；Windows 使用 DPAPI/Credential Manager 或评审通过的等价方案。
- 二维码与 `.echoday-pair` 文件不得含私钥或长期可复用密码。
- 主机确认页显示设备名与由双方密钥材料导出的六位校验码。
- 邀请失败达到限制、成功、过期或用户取消时立即失效。
- 撤销设备后关闭现有会话并拒绝其公钥；重新加入必须重新配对。
- TLS 负责协商传输会话密钥；应用会话使用 256-bit 随机短期 token，默认 12 小时失效且只驻留内存。
- 每个应用请求还必须由设备 Ed25519 私钥签名，并绑定方法、路径、body 哈希、时间戳和一次性 nonce；长期私钥不作为 Bearer token 传输。

S3 使用 Dart TLS、安全随机源和成熟密码库实现 RSA 自签名主机证书、SHA-256 证书指纹及 Ed25519 设备签名，没有自行设计加密算法。证书与私钥由操作系统安全存储承载，不进入 SQLite 或 JSON 备份。

## 4. 输入处理

### 保留历史的重新配对与等价冲突修复（1.0.8-dev.6）

- 已配对客户端重新配对必须匹配原同步组、TLS 指纹、主 PC 设备 ID 和公钥，使用原客户端私钥签署新邀请；仍需要新的一次性邀请、六位设备码核对及主 PC 人工批准。不删除身份、操作日志、游标或任务，也不重新生成任务基线。
- 主 PC 只允许相同同步组、同设备 ID 且公钥一致的既有客户端重新确认；不能将主机身份改登记为客户端，不能用另一密钥覆盖已有设备。撤销状态只能在主 PC 再次批准后解除，原备注及创建信息保留。
- 等价判断仅用于判断是否存在业务冲突，不用于 operation ID 重放判定、签名或序列校验；这些安全校验保持严格。
- 允许补齐旧版缺失的 TODO `isFuture=false`、`isAbandoned=false` 和完成/放弃的空时间字段。自动创建/完成/放弃/删除时间按既有 SQLite 秒级持久化精度比较；计划执行/DDL 时间仍比较完整时间点，未知字段和真实值差异不会忽略。
- 读取待处理冲突时，事务性核算已保存的 `concurrentFieldEdit`。仅当原始两条操作仍在、身份/对象/字段一致且等价时，标记旧误报为已处理；保留冲突原记录及原胜出操作引用，不改写任何任务、日志、设备身份或游标。删除对编辑的冲突不自动处理。两端升级后独立执行同一规则，无需伪造批量“用户选择”操作。

### 已配对客户端的连接地址更新（1.0.8-dev.4）

- “更新 WLAN”二维码只包含当前实际监听的地址/端口、接口名称、同步组、主 PC 设备 ID、证书指纹及 10 分钟有效期；不包含邀请 token、会话凭据或私钥，也不能用于首次配对。
- 客户端首先校验格式、有效期，以及同步组、主 PC ID、已固定证书指纹的一致性。随后向新地址验证 TLS 指纹并完成原设备签名的会话认证，成功后才保存及切换连接配置。
- 对不匹配身份、过期码、错误证书或无法认证的主机，保留原连接配置及本地任务；不创建新的设备身份、不删除配对、不重置同步游标。
- 保存的地址列表、默认地址属于设备本地同步配置，不写入任务 JSON 备份，也不跨设备同步。临时切换不改变默认项。
- 更新码不是秘密授权材料，但包含网络地址，不应写入日志或公开发布。客户端与主 PC 之间仍需具备网络可达性。

- gzip 限制按解压后的真实字节数执行，防止压缩炸弹。
- JSON 在完整解析前也设置读取上限和超时。
- 协议/schema 不兼容、跨组 operation、未知字段类型、外键损坏均在事务提交前拒绝。
- 同一 transaction 中任何一条失败，整批事务回滚。
- 标题和备注以纯文本处理；同步层不执行 HTML、Markdown、路径或命令。
- 网络地址由结构化 endpoint 类型解析，不能拼接到 shell 命令。
- 快照导入复用备份实体校验，但不复用“同 ID 跳过”的备份合并算法。

## 5. 日志脱敏清单

允许记录：

- 结构化错误码；
- 协议版本、schema 版本和平台类别；
- 批次操作数量、字节数和耗时；
- 截断或单向哈希后的 operation/device/group ID；
- 游标差值、重试次数和状态转换；
- 不含用户正文的异常类型与内部调用位置。

禁止记录：

- TODO 标题、备注、分类名、标签名和完整 payload；
- 私钥、公钥原文、会话密钥、token、连接码、二维码 URI、Authorization 与 Cookie；
- 完整 IP、MagicDNS 名称、端口组合和本地文件路径；
- 设备备注、用户邮箱和数据库/备份正文；
- 未脱敏的请求/响应 body；
- 包含上述内容的异常 message 或 `toString()`。

日志辅助函数必须默认拒绝敏感字段，不能依赖调用方记得手工遮盖。Release 日志不输出堆栈到普通用户界面。

## 6. 安全事件与恢复

- 认证失败、nonce 重放、operation ID 内容冲突和连续失败邀请属于安全事件。
- 安全事件只记录时间、错误码及截断身份哈希，不记录凭据。
- 网络或认证失败不得删除未上传的本地 change。
- 首次配对、角色切换、schema 升级与覆盖快照前必须创建安全备份。
- 被撤销设备本地仍保留 TODO；只清除同步身份、会话和游标。
- 用户应能停止主机服务；停止后立即释放监听 Socket，并清除内存会话密钥。

## 7. S3 安全验收门槛

- 未配对客户端不能读取任务数量、正文或设备列表。
- 过期/已使用邀请、撤销设备和错误主机指纹均被拒绝。
- 重放、乱序缺口、超限 gzip/JSON/批次在写库前被拒绝。
- fuzz/损坏 payload 不导致服务退出或部分事务。
- 关闭服务后端口立即不可连接。
- 自动化检查证明日志不含测试用标题、备注、token、私钥和完整地址。
- 局域网及 Tailscale 场景都执行相同认证，不存在“可信网络免认证”分支。
